# RemWay

**RemWay** is a modern frontend coding challenge platform built with React 19, TanStack Router, TanStack Query, Tailwind CSS v4, ShadCN UI, and Supabase. It features an advanced theming system, modular routing, efficient state and data management, and **AI-powered feedback** using Google Gemini 2.5 Pro.

---

## Features

- **React 19** with TypeScript for type-safe development
- **TanStack Router** for declarative, file-based routing with auto code-splitting
- **TanStack Query** for server state management and caching
- **Tailwind CSS v4** with custom theming and dark mode support
- **ShadCN UI** components for a polished, accessible UI
- **Supabase** as a backend and authentication provider
- **AI Feedback System** with Gemini 2.5 Pro for automated challenge assessment
- **Resubmission Tracking** with improvement comparison across attempts
- **Mismatch Detection** to catch wrong project submissions
- Modular project structure for scalability and maintainability

---

## AI Feedback System

RemWay includes a comprehensive AI feedback system that:

- ✅ **Generates detailed feedback** for challenge submissions using Gemini AI
- ✅ **Tracks submission history** and compares improvements over time
- ✅ **Detects mismatches** when wrong projects are submitted
- ✅ **Provides structured analysis** across 4 key areas (best practices, code formatting, functionality, accessibility)
- ✅ **Offers actionable recommendations** for next steps and learning resources
- ✅ **Priority-based code fetching** from GitHub (prioritizes src/ files over config)

### How It Works

1. **Submit**: User provides GitHub repo URL + live site URL
2. **Validate**: URLs are validated client-side and server-side
3. **Fetch**: System fetches source code from GitHub with smart prioritization
4. **Analyze**: Gemini AI analyzes code, design, and functionality
5. **Compare**: If resubmission, compares with previous feedback
6. **Display**: Structured feedback with scores and recommendations

## Getting Started

### Prerequisites

- [Bun](https://bun.sh/) installed (preferred package manager and runtime)
- Node.js (optional, if using npm/yarn instead)
- Supabase account with project set up
- Gemini API key (free tier available)

---

### Installation

1. Clone the repository:

   ```bash
   git clone https://github.com/yourusername/remWay.git
   cd remWay
   ```

2. Install dependencies with Bun:

   ```bash
   bun install
   ```

3. Set up environment variables:

   ```bash
   cp .env.example .env.local
   # Edit .env.local with your credentials
   ```

---

### Development

Run the development server with:

```bash
bun run dev
```

This will start Vite and open your app at `http://localhost:5000`.

---

### Build

To build the project for production:

```bash
bun run build
```

---

### Formatting and Linting

The project uses ESLint and Prettier. All three commands run in CI on every
pull request.

- Lint with ESLint:

  ```bash
  bun run lint
  ```

- Format all files with Prettier:

  ```bash
  bun run format
  ```

- Check formatting without writing (what CI runs):

  ```bash

  ```

```
 ┣ lib/              # Utility functions, API clients (supabase, queryClient)
 ┣ providers/        # React context providers (QueryProvider, ThemeProvider)
 ┣ routes/           # TanStack Router file-based routes
 ┣ services/         # Domain-specific services (feature modules)
 ┃ ┣ ai/            # AI feedback generation (Gemini integration)
 ┃ ┣ challenges/    # Challenge listing, details, submission
 ┃ ┣ feedback/      # Feedback display, components, hooks
 ┃ ┣ home/          # Landing page components
 ┃ ┣ profile/       # User profile management
 ┃ ┣ resources/     # Learning resources
 ┃ ┗ roadmap/       # Learning paths
 ┣ styles/           # Global and feature-specific CSS
 ┣ types/            # TypeScript type declarations
 ┣ main.tsx          # Entry point
 ┣ routeTree.gen.ts  # Generated by the TanStack Router plugin — do not edit
 ┗ index.css         # Global CSS with Tailwind imports

docs/                # Architecture, AI system and user documentation
scripts/             # One-off maintenance and debugging scripts (run with bun)
```

## Configuration

- **Theme management:** via `ThemeProvider` context wrapping your app
- **Server state:** TanStack Query, with hooks under `services/*/use*.ts`
- **Client state:** React context and local component state — there is no
  dedicated store library
- **API calls:** handled in `services/*/api.ts` using Supabase client
- **Routing:** configured with TanStack Router in `routes/` and `routeTree.gen.ts`

## Known Issues

### API keys are exposed in the client bundle

**Severity: high.** `VITE_GEMINI_API_KEY` and `VITE_GITHUB_TOKEN` are read
directly in browser code (`src/services/ai/api.ts`, `src/services/ai/githubFetcher.ts`).
Any `VITE_`-prefixed variable is inlined into `dist/assets/*.js` by Vite at
build time and is public by design — anyone who loads the deployed site can
extract both and spend your quota.

The fix is to move the Gemini and GitHub calls server-side:

1. Add Vercel serverless functions (`api/generate-feedback.ts`,
   `api/fetch-repo.ts`) that hold the credentials.
2. Rename the variables to server-only `GEMINI_API_KEY` and `GITHUB_TOKEN`
   (no `VITE_` prefix) in the Vercel project settings.
3. Point the client at those endpoints instead of at Google and GitHub.
4. **Rotate both keys as part of the change** — assume the currently deployed
   ones are already compromised.

### Supabase types are out of sync with the database

`src/types/supabase.ts` declares 2 of the 8 tables the app queries
(`challenge_submissions`, `challenge_feedback`), and the columns it does
declare omit several the code reads. Newer `@supabase/supabase-js` resolves
unknown tables to `never`, so affected call sites carry documented type
assertions with a pointer back to this issue.

Regenerate against the live database to remove them:

```bash
bunx supabase gen types typescript --project-id <your-project-id> > src/types/supabase.ts
```

### Remaining dependency advisories

`bun audit` reports 15 advisories, all in transitive build-time dependencies
(`rollup`, `postcss`, `picomatch`, `minimatch`, `brace-expansion`, `diff`,
`flatted`). They are pinned by the current major versions of Vite, ESLint and
Tailwind and cannot be resolved without those major upgrades. None of them
ship in the production bundle.
